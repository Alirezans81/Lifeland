# Lifelands Game Explorer

A Persian (RTL) Game Explorer for [Lifelands](https://lifelands.ir), built with Next.js 16 (App Router) and strict TypeScript. It renders games from `GET https://lifelands.ir/api/v1/games` as a searchable, filterable, sortable grid. This is a single-section frontend assignment.

> **Status:** project setup only (Next.js scaffold, RTL layout, Persian font). The Game Explorer features below are planned and not implemented yet. See `context/progress-tracker.md` for the current state.

## Next.js Notes

- **Read the bundled docs first.** The generated `AGENTS.md` warns that this Next.js version differs from older releases. Docs ship with the package in `node_modules/next/dist/docs/`; check them before writing framework code.
- **Cache Components and Partial Prefetching are enabled.** `next.config.ts` sets `cacheComponents: true` and `partialPrefetching: true`. This changes how server fetching and caching are written, so verify the `revalidate` approach against the docs before implementing the server fetch.
- **Tailwind via PostCSS.** `postcss.config.mjs` enables `@tailwindcss/postcss`, as in the Next.js CSS docs; Turbopack runs PostCSS automatically. `app/globals.css` starts with `@import "tailwindcss"`.
- **Typed layouts.** The root layout is typed with the generated `LayoutProps<"/">`. Route types are generated by Next.js, and `next-env.d.ts` is git-ignored.
- **RTL is manual.** Next.js has no RTL switch. `app/layout.tsx` sets `<html lang="fa" dir="rtl">` once, and the Vazirmatn variable `--font-vazirmatn` is mapped to `--font-sans` in `app/globals.css`.
- **Logical properties only.** Use `ps-*`, `pe-*`, `ms-*`, `me-*`, `border-s-*`, and `text-start`; never `left`/`right`.
- **Server Components by default.** `'use client'` is for leaf interactive components only. The page itself is never a Client Component.

## Project Rules

Violating any of these gets the submission rejected:

- TypeScript `strict: true`; no `any`, `@ts-ignore`, or `as unknown as`.
- The initial fetch happens in a Server Component, never in `useEffect`.
- The browser never calls the Lifelands API directly; client fetches go through a server proxy / route handler.
- Types come from the real API response, not from a tutorial or another project.
- Persian normalization is mandatory; `lib/` has zero React imports.
- No `console.log`, unused files, dead code, or commented-out blocks.
- No committed `.env` or `node_modules`.
- This README is mandatory and includes an honest AI Usage section.

## Planned Features

- First 12 games server-rendered, wrapped in `<Suspense>` with a skeleton that matches the final card dimensions.
- Search over `title` and `companyName` with a 300ms debounce and Persian normalization (ی/ي, ک/ك, Persian/Arabic digits to Latin, ZWNJ removal, whitespace collapse).
- Config-driven filters: vendor (multi-select), category, score range, plus one extra filter documented here.
- Sort by `score`, `runCount`, `seenCount`, `like`, and a blended quality score.
- Favorites persisted in `localStorage`, with a favorites-only filter.
- Race-safe load more (`AbortController` or request-ID guard).
- URL as the single source of truth for filters, so shared links and back/forward restore the exact view.
- Empty state with a reset action; image fallback that keeps card dimensions.

## API Notes

Verified against the live endpoint on 2026-10-19:

- Envelope is `{ state, data }`. `data` includes `pageId`, `eachPerPage` (12), `total` (729), and `games[]`.
- Pagination uses `?pageId=N`. `?page=N` is ignored and returns page 1. A page past the end returns an empty `games` array.
- Category titles have trailing spaces and must be trimmed. `companyName` can be empty or inconsistent. Empty `vitrinThirdPartyVendors` arrays are common.
- `image` is a relative path; the public base URL is not confirmed yet.
- The `creator` object contains personal data and is never forwarded to the client.

## Design Decisions and Trade-offs

Decided so far:

- Tailwind CSS for styling, Vazirmatn for typography.
- `?pageId=N` for pagination.
- The server maps API games to a minimal type before they reach the client.

To be decided and documented here as they are implemented: load more vs pagination, `revalidate` value and why, empty-vendor policy, `total` vs array length mismatch handling, quality score formula, extra filter, TypeScript decisions (vendor union and guard, filter-state union, `SortKey`), and which components are Server Components and why.
